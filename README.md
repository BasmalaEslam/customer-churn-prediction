# Retention Intelligence

Customer churn classification, leakage-safe preprocessing, baseline comparison, validation threshold and intervention ranking.

**Runnable learning/portfolio demo, not a production-ready product.** Generated data is clearly synthetic. Local evaluation reports are evidence about this demo only. Optional integrations need your own setup.

## Run on Windows (PowerShell, Python 3.11 recommended)

Open a terminal **inside this project folder**. Run each line separately:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py train
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe app.py demo
.\.venv\Scripts\python.exe app.py serve
```

Then open **http://127.0.0.1:8101**. Ctrl+C stops the service. This avoids PowerShell activation-policy problems. If Python 3.11 is not installed, install it first; `py --list` shows installed versions.

Linux/macOS:

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py train
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python app.py serve
```

## API

GET `/health` returns service status. POST endpoints accept JSON objects; examples are in `samples/`. POST `/report` returns measured local evaluation. The UI includes business result cards, tables, source evidence and a demand chart, plus a full JSON inspector. It calls the real service.

- POST `/predict` — sample: `samples/predict.json`
- POST `/batch` — sample: `samples/batch.json`
- POST `/report` — sample: `samples/report.json`

## Reproducibility and operational limits

- Python 3.11 and exact dependency versions are recorded. Models are regenerated with fixed seeds; timing can vary.
- Re-run `train` after changing training data/policies. Do not load joblib files from untrusted sources; they are Python serialization.
- Data generators run only if model CSV input is absent, except invoice history, which is regenerated by its demonstration training command.
- `.env.example` is a reference, **not automatically loaded**. Set variables in your shell; never commit keys.
- CSV exports escape formula prefixes in untrusted text cells.
- SQLite data lives in `runtime/`, excluded from Git. It is not encrypted. Back up privately; delete the folder to reset the demo after stopping the server.
- Local service has no authentication, tenant isolation, rate limiting or reviewer identity verification. Bind to loopback and use fictional data. A public deployment requires these controls plus TLS, monitoring, migrations and access policies.
- Optional LLM output is parsed and validated but may still misinterpret facts. Human review is required.
- Included GitHub Actions and Dockerfile were authored; they were not executed in this environment. See `reports/verification.json` for what was actually tested.
